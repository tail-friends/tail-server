# 종 일괄 등록

노션 "종 원본 표"(종 확장 계획 페이지 안)에서 검수한 종을 관리자 API(`POST /api/v1/admin/species`)로 한꺼번에 넣는다.
종은 마이그레이션으로 넣지 않는다. 처음 10종만 마이그레이션이고, 그 뒤로는 이 스크립트나 관리자 웹으로 넣는다.

## 순서

1. 노션 표에서 넣을 종의 상태를 **검수 완료**로 바꾼다. 급여·탈피·온습도 값은 출처가 있는 것만 적는다.
2. 표 오른쪽 위 `…` → 내보내기 → CSV로 내려받는다.
3. 먼저 미리 본다.
   ```bash
   python3 scripts/species-import/import_species.py 종원본표.csv --dev-login 관리자 --dry-run
   ```
4. 문제가 없으면 `--dry-run`을 빼고 다시 돌린다. 이미 있는 종의 값(예: 처음 10종의 온습도)도 고치려면 `--update`를 붙인다.
5. 등록된 행은 노션에서 상태를 **등록됨**으로 바꾼다.

## 동작

- 상태가 `검수 완료`인 행만 보낸다. `조사 중`, `등록됨`은 보내지 않는다.
- 서버에 이미 있는 이름은 건너뛴다. 그래서 여러 번 돌려도 같은 종이 두 번 생기지 않는다.
- `--update`를 주면 이미 있는 종도 건너뛰지 않고 CSV 값으로 수정한다(`PATCH`). CSV에서 비어 있는 칸은 보내지 않으므로 서버 값이 그대로 남는다. 서버 값을 비우는 것은 이 스크립트로 할 수 없다. 이름을 바꾸는 것도 안 된다(이름으로 같은 종을 찾기 때문).
- 별칭은 쉼표로 나눈다. 가시는 체크하면 `true`.
- 행마다 `등록` / `수정` / `건너뜀` / `실패`(서버 에러 코드와 이유)를 출력한다. 실패가 하나라도 있으면 종료 코드가 1이다.

## 관리자 토큰

| 환경 | 방법 |
|---|---|
| 로컬 | `--dev-login 이름`: 테스트 로그인(`POST /api/v1/dev/login`, `role: ADMIN`)으로 토큰을 받는다. 서버를 `DEV_LOGIN_ENABLED=true`로 띄워야 한다 |
| 개발·운영 서버 | 관리자 계정의 액세스 토큰을 환경 변수 `TAIL_ADMIN_TOKEN`에 넣고 `--base-url`로 서버 주소를 준다. 토큰은 30분이면 만료된다 |

```bash
TAIL_ADMIN_TOKEN=... python3 scripts/species-import/import_species.py 종원본표.csv --base-url https://{서버 주소}
```

토큰은 명령 기록이나 문서에 남기지 않는다.
