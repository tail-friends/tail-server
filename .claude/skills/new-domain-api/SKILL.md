# 도메인 API 만들기

AGENTS.md 2부(서버 규칙)를 따른다. 작업 전에 `start-task`로 이슈와 브랜치를 준비한다.

## 0. 명세 확인

- 노션 API 명세서에서 경로, 요청, 응답, 에러를 확인한다. 노션 ERD에서 테이블과 컬럼을 확인한다.
- 노션을 볼 수 없거나 명세가 비어 있으면 추측하지 말고 사람에게 묻는다.
- 만들 파일 목록을 먼저 보여주고 진행한다.

## 1. 마이그레이션

`src/main/resources/db/migration/V{yyyyMMddHHmm}__create_<테이블>.sql`

```sql
CREATE TABLE animals (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id     BIGINT       NOT NULL REFERENCES users (id),
    name        VARCHAR(30)  NOT NULL,
    created_at  TIMESTAMPTZ  NOT NULL,
    updated_at  TIMESTAMPTZ  NOT NULL
);
CREATE INDEX idx_animals_user_id ON animals (user_id);
```

- 버전 시각은 작성 시각(`date +%Y%m%d%H%M`)으로 한다.
- 이미 머지된 마이그레이션은 고치지 않는다.

## 2. 엔티티 (`{도메인}/domain`)

```java
@Getter
@Entity
@Table(name = "animals")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Animal extends BaseTimeEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "user_id", nullable = false)
    private User user;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 10)
    private Sex sex;
}
```

- `@Setter` 없이 변경 메서드(`update(...)`)를 둔다.
- 컬럼 길이·NULL 여부를 마이그레이션과 맞춘다. 다르면 `ddl-auto: validate`에서 앱이 뜨지 않는다.

## 3. 레포지토리 (`{도메인}/repository`)

- `JpaRepository<Animal, Long>`를 상속한다.
- 소유권 확인용 조회를 둔다. 예: `Optional<Animal> findByIdAndUserId(Long id, Long userId)`

## 4. DTO (`{도메인}/dto`)

- `record`로 만든다. 요청은 Bean Validation, 응답은 `static from(엔티티)` 팩토리.

## 5. 서비스 (`{도메인}/service`)

- 클래스에 `@Transactional(readOnly = true)`, 쓰기 메서드에 `@Transactional`.
- 없거나 남의 데이터면 `throw new BusinessException(ErrorCode.XXX_NOT_FOUND)`.
- 엔티티가 아닌 응답 DTO를 반환한다.

## 6. 컨트롤러 (`{도메인}/controller`)

```java
@Tag(name = "Animal")
@RestController
@RequiredArgsConstructor
@RequestMapping("/api/v1/animals")
public class AnimalController {

    private final AnimalService animalService;

    @Operation(summary = "개체 등록")
    @PostMapping
    public ApiResponse<AnimalResponse> create(@Valid @RequestBody AnimalCreateRequest request) {
        return ApiResponse.success(animalService.create(request));
    }
}
```

## 7. 테스트

- 서비스의 규칙 로직은 단위 테스트를 쓴다.
- 컨트롤러는 `@WebMvcTest(AnimalController.class)` + `@WebMvcTestSupport` + `@WithMockUserId`, 서비스는 `@MockitoBean`.
- 성공 응답 형식과 주요 에러 코드(검증 실패, NOT_FOUND)를 검증한다.
- 통합 테스트: `{도메인}/integration/XxxIntegrationTest`가 `IntegrationTestSupport`를 상속해 실제 DB로 API를 호출한다. 마이그레이션과 엔티티가 맞는지(`ddl-auto: validate`)도 여기서 검증된다.
- 로컬에 Docker가 없으면 통합 테스트는 건너뛰어진다. 그때는 CI 결과로 확인하고, 그 전까지 "실제 DB에서 확인했다"고 쓰지 않는다.

## 8. 마무리

- `./gradlew build` 통과를 확인한다.
- 커밋은 나눈다: 마이그레이션 → 엔티티·레포지토리 → 서비스·DTO → 컨트롤러 → 테스트.
- 새 에러 코드를 만들었으면 노션 API 명세서에도 추가해야 한다고 사람에게 알린다.
